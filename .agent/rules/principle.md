## SECTION 1: CORE DIFFERENTIATION

我们的护城河不是流量技巧，而是**不可复制的真实**：

| 维度         | 定义                                                             | AI 生成内容时的指导                            |
| :----------- | :--------------------------------------------------------------- | :--------------------------------------------- |
| **思考深度** | 追求"穿透"而非"快"，让读者感到"被看见"或"被点醒"                 | MUST: 呈现思考结果，不卖弄底层理论             |
| **硬核质量** | 真正有价值的是不为平台算法写的文章 (`Garden/Tech`, `Garden/Biz`) | MUST: 平台文章是硬核内容的"蒸馏版"             |
| **情感陪伴** | 暴露脆弱、承认失败、在场陪伴                                     | MUST: 体现真实人的温度，这是 AI 无法替代的部分 |

**Tech Metaphors (表达工具，非内容本身)**:
- Pre-training → 通识教育 | Fine-tuning → 职业深耕 | RAG → 第二大脑
- Alignment → 知行合一 | Context Window → 精力管理 | Agent → 生活自动化

## SECTION 2: CONTENT GENERATION RULES

### 2.1 MUST (必须遵守)

```
- 记录"今天的风浪"（困难）和"航向的调整"（思考过程）
- 优先"内心平和"胜过"效率提升"
- 追求真实反馈，而非虚荣指标（点赞数）
- 每个实验必须能在 48 小时内启动 MVP
- 每次实验结束（无论成败）必须输出一篇日志
```

### 2.2 MUST NOT (禁止)

```
- 事后诸葛亮（不要等靠岸后才写日记）
- 标题党（不要为流量牺牲真实）
- 贩卖焦虑（只列问题不给解法）
- 说教语气（不说"你应该"，要说"我试了"）
- 阶段 1 就卖课（信任未建立）
```

### 2.3 SHOULD (建议)

```
- 使用航海隐喻包装内容（对外感性外壳）
- 内部使用算法思维操作（对内理性内核）
- 一鱼多吃：1 Blog = 1 公众号 + 1 知乎 + 3 小红书 + 5 Twitter
```

### 6.3 Transformation Workflows

内容转换通过模块化的 AI 工作流实现，存放于 `.agent/workflows/` 目录：

```yaml
available_workflows:
  - file: gen-blog.md
    command: /gen-blog
    platform: Blog (Quartz)
    description: Blog排版优化专家，SEO优化
    
  - file: gen-wechat.md
    command: /gen-wechat
    platform: 公众号
    description: 公众号深度长文转换
    
  - file: gen-zhihu.md
    command: /gen-zhihu
    platform: 知乎
    description: 知乎专栏/问答生成
    
  - file: gen-redbook.md
    command: /gen-redbook
    platform: 小红书
    description: 小红书爆款文案专家
    
  - file: gen-tweet.md
    command: /gen-tweet
    platform: Twitter/X
    description: Twitter 推文串生成专家
```

**Routing Logic (调用决策)**:

```
WHEN user provides input_content:
  
  IF target_platform == "小红书":
      EXECUTE: /gen-redbook
      INPUT: input_content
      
  ELIF target_platform == "Twitter":
      EXECUTE: /gen-tweet
      INPUT: input_content
      
  ELIF target_platform == "公众号":
      EXECUTE: /gen-wechat
      INPUT: input_content
      
  ELIF target_platform == "知乎":
      EXECUTE: /gen-zhihu
      INPUT: input_content
      
  ELIF target_platform == "全平台" OR target_platform == None:
      # One Source Multi-Use: 依次执行所有工作流
      FOR workflow IN [gen-wechat, gen-zhihu, gen-redbook, gen-tweet]:
          EXECUTE: workflow
          INPUT: input_content
```

**Workflow 设计原则**:
- 每个 workflow 独立维护，遵循 Gemini.md 中的 MUST/MUST NOT 规则
- 工作流内部引用本文档的 `tone`, `core_differentiation`, `content_pillars` 参数
- 输出格式统一，便于复制粘贴到对应平台

### 6.5 Image Generation Guidelines (配图生成)

```yaml
image_generation:
  tool: generate_image
  blog_images: content/attachments/
  platform_images: content/platform/{date}_{topic}/{platform}/images/
  
  image_types:
    cover:
      purpose: 封面/首图，吸引点击
      style: 与航海日志风格一致（手绘感、探索感）
      dimensions: 按平台要求
      
    concept_diagram:
      purpose: 概念图/流程图，解释复杂概念
      style: 简洁、专业、信息清晰
      
    quote_card:
      purpose: 金句卡片，便于分享
      style: 简约文字为主，强调金句
      
    comparison:
      purpose: 对比图，展示 before/after 或 A vs B
      style: 双栏对比，视觉清晰

platform_specs:
  小红书:
    cover: 3:4 竖版，吸睛标题叠加
    cards: 1:1 方形金句卡片
    
  公众号:
    cover: 2.35:1 横版
    inline: 按内容需求
    
  Twitter:
    cover: 16:9 横版
    thread_images: 1:1 或 16:9
    
  Blog:
    cover: 选填
    inline: 配合内容，注意 alt 文本
```

**Image Prompt 原则**:
```
MUST:
- 使用中文生成 prompt（工具支持中文）
- 明确指定：主题、风格、尺寸、配色
- 与"航海日志"视觉风格保持一致

SHOULD:
- 避免真人照片（使用插画/概念图）
- 使用蓝色、海洋色系作为主色调
- 加入"手绘感"、"探索感"元素
```

## SECTION 8: MONETIZATION STAGES

```yaml
stages:
  - stage: 1
    name: 信任积累
    goal: 建立"被信任的解决方案"形象
    metrics:
      - 真实反馈数 >= 50/月
      - 至少 3 个"铁粉"主动私信交流
    duration: 3-6 月

  - stage: 2
    name: 产品雏形
    goal: 推出第一个付费产品
    metrics:
      - 首单成交
      - 复购率 > 30%
    duration: 6-12 月
    transition_condition: 当有人主动问你要付费产品时才启动

  - stage: 3
    name: 规模化
    goal: 产品矩阵 + 被动收入
    metrics:
      - 月收入 >= 主业 50%
      - 时间投入 <= 10h/周
    duration: 12-24 月
    transition_condition: 当单个产品复购稳定且口碑正向时才扩展
```

## SECTION 9: WEEKLY REVIEW PROTOCOL

```yaml
schedule: 每周日
duration: 30-60 min

steps:
  1_data_collection:
    action: 从各平台后台导出本周数据
    metrics: [阅读量, 点赞, 评论, 新增关注]
    
  2_input_review:
    question: 本周习得了哪些新工具/技能？哪些已实际应用？
    
  3_feedback_analysis:
    question: 哪条内容获得了"真实反馈"？为什么？
    
  4_system_state:
    question: 本周"内心平和度"的波动如何？是否触发停损？
    
  5_next_week:
    action: 基于以上，调整下周的内容方向或节奏

output: weekly_review_YYYYMMDD.md → Garden/Life/
```
