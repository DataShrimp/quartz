# 项目宪法 - 数据小虾米的Quartz数字花园

## 🎯 项目定位

这是一个基于Quartz构建的个人知识管理与项目展示系统，属于"数据小虾米"（Data Shrimp）的数字花园，核心目标积累个人 IP 资产并对外宣传。

## 📁 目录结构设计

### 核心内容组织

```
content/
├── index.md              # 主页 - 项目展示与服务介绍
├── About.md              # 个人介绍
├── Garden/               # 知识花园 - 思考与学习记录
│   ├── Tech/            # 技术文章 (AI模型分析、技术趋势)
│   ├── Biz/             # 商业思考 (一人公司实践、商业模式)
│   └── Life/            # 生活感悟
├── Projects/            # 项目展示 - Build in Public
│   ├── AI-Company/      # 一人公司数字基建项目
│   └── Antigravity/     # AI灵感捕获系统
├── Services/            # 服务介绍
│   ├── AI-Consulting/   # AI咨询服务
│   ├── Workflow-Automation/  # 工作流自动化
│   └── Idea-Navigator/  # 灵感导航服务
├── templates/           # 文章模板
└── attachments/         # 附件资源
```

## 🏗️ 内容架构原则

### 1. 知识网络化
- 使用Quartz的Wiki链接功能 `[[双中括号]]` 构建知识关联
- 强调概念间的连接而非孤立的文章
- 鼓励通过链接进行知识探索

### 2. 项目透明化
- 所有核心项目都采用"Build in Public"方式
- 架构设计、成本分析、技术选型完全公开
- 展示真实的项目状态（包括进行中的工作）

### 3. 服务产品化
- 将个人能力包装成可复制的服务产品
- 明确服务范围、目标客户、价值主张
- 提供清晰的联系方式和转化路径

## ✍️ 内容创作规范

### Frontmatter模板
```yaml
---
title: 文章标题
description: SEO优化的简短描述
tags:
  - 标签1
  - 标签2
date: YYYY-MM-DD
---
```

### 内容类型定义

1. **数字还原 (Garden/)**
   - 深度技术解析，Tech
   - 生活感悟经验，Life
   - 产品商业思考，Biz

2. **项目文档 (Projects/**)
   - 架构设计文档
   - 成本分析
   - 实施进度
   - 技术栈选择理由

3. **服务说明 (Services/**)
   - 服务内容描述
   - 适合人群
   - 实施案例
   - 联系方式

### 写作风格指南

1. **第一人称视角**：以"我"的视角分享经验和思考
2. **实用导向**：强调可操作、可复制的实践
3. **数据支撑**：提供具体的数据、成本、配置信息
4. **视觉辅助**：善用表格、图表、代码块

## 🔗 链接策略

### 内部链接网络
- 项目间相互引用：`[[Projects/AI-Company/Architecture]]`
- 概念解释链接：技术术语链接到相关解释文章
- 服务展示链接：从技术文章链接到相关服务

### 外部引用规范
- 引用技术报告、官方文档
- 提供源链接便于追溯
- 优先引用权威来源

## 🚀 发展目标

### 短期目标
- 完善核心项目文档
- 建立技术文章更新机制
- 优化SEO和用户体验

### 长期愿景
- 成为一人公司实践的参考案例
- 建立AI原生工作法的知识体系
- 通过服务实现可持续发展

## 📊 内容质量标准

1. **原创性**：优先分享第一手实践经验和思考
2. **实用性**：每个知识点都应有实际应用场景
3. **时效性**：技术内容需保持更新，标注时间
4. **完整性**：项目文档应包含完整的设计思路和实施细节

## 🛠️ 维护机制

- 定期更新项目进展
- 技术文章随技术发展迭代
- 服务内容根据市场反馈调整
- 保持链接有效性
