# Video Script Generator（短视频导流脚本生成）

将长文内容浓缩为 **30 秒竖屏短视频脚本**，用于视频号、抖音等平台导流至公众号/博客。

---

## 1. 第一优先级：标题 + 前 3-5 秒

> ⚠️ **这是整个脚本最重要的部分。** 视频号/抖音的用户在前 3-5 秒内决定是否继续观看。标题和开头必须在瞬间抓住注意力，否则后面的内容再好也没用。

### 1.1 标题设计原则

标题是用户在信息流中看到的第一层筛选，直接决定点击率。

**有效标题公式**：

| 公式 | 模板 | 示例 |
| :--- | :--- | :--- |
| **反常识** | "[主体]不再[常规认知]！" | "谷歌不再卖产品！AI 时代的生存秩序变了！" |
| **数字+规模** | "[数字]个信号看懂[事件]" | "5 个信号看懂 Google I/O 2026 的真正野心" |
| **疑问+痛点** | "[事件]后，[目标人群]怎么办？" | "巨头全栈闭环，一人公司如何借力突围？" |
| **强判断** | "[事件]的本质是[判断]" | "从芯片到购物车：谷歌全站 AI 野心远比想象中的大" |

**标题禁忌**：
- ❌ 平铺直叙（"Google I/O 2026 发布会总结"）
- ❌ 没有冲突感（"谷歌发布了一些新产品"）
- ❌ 太长（视频号标题超过 20 字会被截断）

### 1.2 前 3-5 秒 Hook 设计

前 3-5 秒的口播和画面，是用户唯一会"免费"给你的注意力窗口。

**有效 Hook 模式**：

| 模式 | 口播示例 | 为什么有效 |
| :--- | :--- | :--- |
| **事件+反转** | "Google I/O 2026 完了。谷歌的野心，远比想象的庞大！" | 先给出"看完了"的确定感，再用"野心庞大"制造悬念 |
| **反常识断言** | "谷歌不再卖产品了。" | 打破用户对科技公司的常规认知，激发好奇心 |
| **数字冲击** | "价格砍半，速度快四倍。一个模型就改变了整个行业格局。" | 具体数字比形容词更有冲击力 |
| **直击痛点** | "你的工作，可能正在被 AI Agent 替代。" | 与用户个人利益直接相关 |
| **悬念前置** | "接下来这 5 个信号，可能改变你对 AI 的认知。" | 承诺价值，给用户留下的理由 |

**Hook 的视觉配合**：
- 前 2 秒画面必须有**强视觉变化**（大字弹出、发光效果、角色出场动作）
- 不要用静态画面开场——用户会以为视频卡了
- 关键词用**金色/黄色高亮**，在小屏幕上也能一眼看到

**Hook 的检验标准**：
> 把 Hook 的口播文字单独拿出来，发给一个不了解背景的人。如果对方会问"然后呢？"——说明 Hook 有效。如果对方说"哦"——说明 Hook 失败。

## 2. 核心理念

### 为什么是 3×10 秒？

当前主流 AI 视频生成工具（Kling、Runway、Pika 等）单次最长生成 **10 秒** 视频。因此脚本按 3 段 × 10 秒设计，后期拼接为 30 秒成片。

### 脚本的定位

脚本不是"口播稿"，而是 **AI 视频生成的完整指令集**，包含：
- 口播文案（配音的原文）
- 画面描述（视频生成工具的 prompt）
- 字幕规范（硬字幕内容与样式）
- 拼接规范（多段衔接方式）
- 发布配套（标题、描述、评论区文案）

## 3. 两种语言场景与配音方案

> ⚠️ 当前 AI 中文 TTS 质量不稳定（发音生硬、专业术语读音异常），因此中文配音统一用**剪映后期制作**，不依赖 AI TTS。

### 场景 A：中文版（视频号 / 抖音）

| 环节 | 方案 |
| :--- | :--- |
| **画面** | AI 视频生成工具（Kling / Runway 等） |
| **配音** | **剪映后期配音**（剪映内置 AI 朗读或手动录制） |
| **字幕** | **剪映自动生成字幕**（基于配音自动识别） |
| **画面文字** | 中文关键词，在剪映中叠加文字层 |

**工作流**：AI 生成画面（不含语音）→ 导入剪映 → 添加配音 → 自动生成字幕 → 叠加画面文字 → 导出

### 场景 B：纯英文版（YouTube Shorts / 国际平台）

| 环节 | 方案 |
| :--- | :--- |
| **画面** | AI 视频生成工具（同上） |
| **配音** | **AI TTS 直接生成**（ElevenLabs / Fish Audio） |
| **字幕** | 英文硬字幕（剪映或 CapCut 添加） |
| **画面文字** | 英文 |

**工作流**：AI 生成画面 → AI 生成英文配音 → 在剪映中拼接画面+配音 → 添加字幕 → 导出

### 语速控制参数

虽然中文版最终用剪映配音，但脚本阶段仍需控制口播字数，确保 10 秒内能自然念完：

| 语言 | 自然语速 | 10 秒安全上限 | 备注 |
| :--- | :--- | :--- | :--- |
| **中文** | 3.5-4 字/秒 | **≤ 38 个汉字** | 作为口播节奏参考 |
| **英文** | 2.5 词/秒 | **≤ 22 个英文单词** | AI TTS 硬性上限 |

> 中文版的字数约束是**节奏参考**（避免念得太赶），英文版是**硬性上限**（AI TTS 超时会被截断）。

## 5. 脚本结构模板

### 5.1 文件头（元信息）

```markdown
# 视频号导流脚本（[语言]版 · 3×10s）

> **总时长**：30 秒 = 3 × 10 秒片段拼接
> **数字人**：[数字人名称]（[参考图文件名]）
> **配音方案**：[剪映后期配音 / AI TTS]
> **字幕**：[剪映自动生成 / 硬字幕]
> **画幅**：9:16 竖屏
> **BGM**：[风格描述]，三段统一
```

### 5.2 每段模板

每段必须包含以下 5 个部分：

```markdown
## 📍 Segment N / 3（起止时间）

### 主题：[一句话概括本段内容]

**口播文案**（X 字 · 约 Y 秒）：

> [逐句口播内容]

**逐句时间轴**：

| 时间 | 口播 | 字数 | 字幕 |
| :--- | :--- | :--- | :--- |
| 0.0-2.5s | [口播句] | [字数] | [字幕内容，关键词加粗] |

**画面描述**：

（用于 AI 视频生成工具的详细画面 prompt）

**首尾帧对齐**：[本段最后 0.5s 的静止画面描述]
```

### 5.3 三段内容编排公式

| 段 | 定位 | 节奏 | 内容要求 |
| :--- | :--- | :--- | :--- |
| **Seg 1** | **Hook（生死线）** + 核心信号 | 快，前 3-5 秒定生死 | 标题呼应的悬念/反常识 + 最有冲击力的 1 个信号 |
| **Seg 2** | 信息密度 | 更快，密集输出 | 2-3 个关键信号快速串联 |
| **Seg 3** | 观点升华 + CTA | 慢，制造回味 | 个人判断/核心观点 + 问题引导式导流 |

### 5.4 结尾深化原则

第三段结尾不能只是"评论区见"的简单 CTA，应做到：

1. **观点升华**：从具体事件抽象到更高层面的判断（如："不再卖产品，而是圈定新秩序"）
2. **个人关联**：连接到用户/一人公司的生存问题（如："个人如何借力？"）
3. **悬念引导**：让用户带着问题去点击公众号链接

> ❌ 弱结尾："完整拆解在公众号，评论区见。"
> ✅ 强结尾："谷歌不再卖产品，而是圈定新秩序。个人如何借力？公众号见。"

### 5.5 首尾金句不重复原则

> ⚠️ 同一个核心判断/金句在整个脚本中只能出现一次。

- 第一段 Hook 用**悬念/反常识/数字冲击**，目的是让用户停留
- 第三段结尾用**核心判断/金句**，目的是制造记忆点和导流动机
- 如果两段使用同一句话，会造成信息冗余，削弱结尾的升华力度

## 6. 多段拼接规范

### 6.1 首尾帧对齐法（推荐）

不依赖转场特效，通过画面内容的自然衔接实现无缝拼接：

```
多段无缝拼接原理（首尾帧完全对齐）：
  1. 静态机位：摄像头位置、角度、高度三段 100% 一致。
  2. 角色位置：数字人始终固定在画面左侧 1/3 处。
  3. 首尾衔接：
     - Seg 1 [9.5-10.0s] 的角色姿态 = Seg 2 [0.0-0.5s] 的角色姿态
     - Seg 2 [9.5-10.0s] 的角色姿态 = Seg 3 [0.0-0.5s] 的角色姿态
  4. 音频拼接：
     - 每段结尾口播收音后，保留 0.5 秒 BGM 铺底
     - 下段紧接起口播，音轨自然重叠
     - 直接在 10s、20s 节点做切片，无需任何转场特效
```

### 6.2 转场特效法（备选）

当首尾帧难以精确对齐时，可在段间添加轻量转场：

| 转场类型 | 适用场景 | 注意事项 |
| :--- | :--- | :--- |
| Zoom in → Zoom out | 同一角色不同动作 | 每段尾 0.5s zoom in，下段头 0.5s zoom out |
| 闪白 | 信息切换明显 | 持续 ≤ 0.3s |
| 溶解（Dissolve） | 情绪转换 | 持续 ≤ 0.5s |

> 建议优先使用首尾帧对齐法。转场特效在竖屏短视频中容易显得廉价。

## 7. 发布配套文案

脚本生成后，同时输出以下发布配套：

### 7.1 视频标题

提供 3-5 个备选标题，覆盖不同风格（参考 §1.1 标题公式）。
视频号标题控制在 **20 字以内**，避免被截断。

### 7.2 视频描述

包含以下要素：
- 1-2 句 Hook（重申核心观点）
- 3-5 个要点列举（对应视频中的信号/论点）
- 导流 CTA（公众号名称 + 文章标题）
- 互动引导（提问促评论）
- 5-8 个标签（#话题标签）

### 7.3 评论区置顶

```markdown
📖 完整版 [字数] 深度拆解：
👉 公众号搜「数据小虾米」

[文章标题或核心一句话]
[2-3 个关键看点]

你觉得 [问题]？评论区聊聊 👇
```

## 8. 工作流程

### Step 1: 内容分析

1. 阅读源文章（公众号文/博客/笔记），提取：
   - **核心观点**（用一句话总结整篇文章）
   - **3-5 个关键信号/论点**（用于分配到三段）
   - **金句**（可直接用于口播的原文短句）
2. 确认数字人形象和参考图路径
3. 确认目标语言场景（中文版 / 英文版）

### Step 2: 先写标题和 Hook

> 标题和 Hook 先于正文撰写，因为它们决定了整个脚本的调性。

1. 根据 §1.1 标题公式，草拟 3-5 个备选标题
2. 根据 §1.2 Hook 模式，为 Seg 1 前 3-5 秒撰写 Hook
3. 用"然后呢？"检验法验证 Hook 有效性

### Step 3: 内容分配

按照 Seg 1（Hook + 核心信号） → Seg 2（信息密度） → Seg 3（观点 + CTA）的公式，将提取的论点分配到三段。

**关键原则**：
- 每段只能有一个主题焦点，不要贪多
- 信息量最大的放 Seg 2（中间段用户注意力最集中）
- 最有记忆点的观点放 Seg 3 结尾（峰终效应）
- 首尾金句不重复

### Step 4: 字数控制与口播撰写

1. 先自由写出每段口播，不限字数
2. 逐段压缩至安全范围（中文 ≤ 38 字 / 英文 ≤ 22 词）
3. 验证方法：逐字计数，含标点和空格
4. 每句口播标注字数和预估时长

### Step 5: 画面描述与 Prompt 撰写

为每段撰写 AI 视频生成工具的 prompt，确保：
- 引用数字人参考图
- 描述角色动作和表情变化
- 描述右侧信息板的文字和图表内容
- 包含时间轴标注（哪秒出现什么元素）
- 指定首尾帧的静止画面（用于对齐拼接）

### Step 6: 验证与输出

1. **字数验证表**：汇总三段的字数、预估时长、安全余量
2. **拼接规范**：首尾帧对齐描述
3. **制作检查清单**
4. **发布配套**：标题、描述、评论区文案

## 10. AI 视频制作工具链

### 场景 A：中文版

| 步骤 | 工具 | 说明 |
| :--- | :--- | :--- |
| 角色一致性 | 参考图引用 | 每段 prompt 均引用同一参考图 |
| 视频生成 | Kling 2.0 / Runway Gen-4 / Pika 2.0 | 只生成画面，不含语音 |
| 三段拼接 | 剪映 | 导入三段画面，按首尾帧对齐切片 |
| 配音 | **剪映内置 AI 朗读** | 选合适的音色，按脚本逐段配音 |
| 字幕 | **剪映自动识别** | 基于配音自动生成中文字幕 |
| 画面文字 | 剪映文字层 | 叠加金色关键词、CTA 卡片等 |
| BGM | 剪映 | 统一铺底 BGM，结尾渐弱 |

### 场景 B：纯英文版

| 步骤 | 工具 | 说明 |
| :--- | :--- | :--- |
| 角色一致性 | 参考图引用 | 同上 |
| 视频生成 | Kling 2.0 / Runway Gen-4 / Pika 2.0 | 只生成画面 |
| 英文配音 | **ElevenLabs / Fish Audio** | AI TTS 直接生成，选温暖自信的男声 |
| 拼接 | 剪映 / CapCut | 画面 + AI 配音拼接 |
| 字幕 | 剪映 / CapCut | 英文硬字幕 |
| BGM | 剪映 | 统一铺底 |

### 视频生成顺序（关键）

```
1. 先生成 Segment 1，确认角色外观和背景调性
2. 用 Segment 1 最后一帧作为 Segment 2 的起始参考（首尾帧对齐）
3. 用 Segment 2 最后一帧作为 Segment 3 的起始参考
4. 三段画面导入剪映拼接
5. 添加配音（中文用剪映 / 英文用 AI TTS）
6. 生成字幕 + 叠加画面文字层
7. 铺 BGM，调整音量平衡
8. 导出成片
```

## 11. 反模式与踩坑记录

### ❌ 标题和 Hook 平淡无力

**问题**：标题用"XX 发布会总结"，开头用"大家好，今天来聊聊…"，用户在 3 秒内划走。
**解决**：标题必须有冲突感/数字冲击（§1.1），Hook 必须在前 3 秒制造悬念或反常识（§1.2）。这是 **最高优先级**。

### ❌ 文案超字导致节奏太赶

**问题**：口播文案字数超过 38 字（中文）或 22 词（英文），10 秒内念不完或念得太赶。
**解决**：严格执行字数控制，每段口播写完后逐字计数验证。英文版尤其注意——AI TTS 超时会被硬截断。

### ❌ 首尾金句重复

**问题**：第一段和第三段使用了同一句金句（如"不是产品，是一套秩序"），造成内容冗余，削弱结尾的升华力度。
**解决**：第一段用悬念 Hook（如野心/反常识），第三段再抛出核心判断。金句只出现一次。

### ❌ 多段转场特效导致跳跃感

**问题**：使用 zoom in/out 转场，但三段的角色位置/背景/光源不一致，拼接后反而更突兀。
**解决**：优先使用首尾帧对齐法（每段最后 0.5 秒角色保持静止，下段第一帧与之完全一致），不添加任何转场特效。

### ❌ 结尾只有简单 CTA

**问题**：第三段只说了"公众号见、评论区见"，缺乏让用户点击的动力。
**解决**：结尾先输出个人判断/观点升华，再用问题式 CTA 引导（如"个人如何借力？公众号见"），让用户带着问题去阅读原文。

## 12. 制作检查清单

```
□ 标题 ≤ 20 字，有冲突感/数字冲击
□ 前 3-5 秒 Hook 能通过"然后呢？"检验
□ 每段口播字数在安全范围内（中文 ≤ 38 字 / 英文 ≤ 22 词）
□ 首尾金句不重复
□ 结尾有观点升华 + 问题引导式 CTA
□ 数字人外观三段一致（服装、配饰、姿态）
□ 背景颜色和粒子效果完全一致，无突变
□ 光源方向一致
□ 字幕字号 ≥ 60pt，底部居中
□ 画面关键词用黄色/金色高亮
□ BGM 跨段连贯，结尾段渐弱
□ 三段拼接处无音频跳跃，剪辑点过渡自然
□ 最终成片总时长 29-30 秒
□ 发布配套文案（标题/描述/评论区）已同步输出
```
