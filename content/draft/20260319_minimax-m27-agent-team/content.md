# MiniMax M2.7 母稿（第五版）

MiniMax M2.7 这次为什么会成为热点，其实不难理解。

一方面，它身上有这一轮大模型竞争里最容易吸引眼球的那几个标签：自我进化、编程能力继续往头部闭源模型靠近、价格还不算离谱。你如果只把它当成一款新模型看，它当然值得看。

如果把参照物放得更具体一点，这种吸引力也很好理解：
- 它有点像这轮厂商都在争的那种“更能自我迭代”的方向，会让人联想到 GPT 这类模型继续往更强自治能力走
- 它在编程和工程任务上又明显不是普通水平，比如公开资料里给出的 **SWE-Pro 56.22%**、**Terminal Bench 2 57.0%**，所以很容易被拿去和 Gemini、Claude 这类头部能力做比较
- 再往另一边看，很多开源模型现在最容易跑起来的，还是“养虾”这种单体 Agent 场景，能真正把复杂工作流跑顺的并不多

所以 MiniMax M2.7 这次会火，不奇怪。

但如果只停在“又一个模型更强了”，我觉得这篇文章就没什么意思了。

我更想写的是它另外一个更值得看的点：**它开始认真回答，多智能体团队到底该怎么组织。**

这件事为什么重要？因为最近我越来越明显地感觉到，单点模型能力当然还在继续提升，但这条线的边际收益，已经没有前两年那么夸张了。

前两年大家拼的是谁的单兵能力更强，谁更像一个无所不能的超级大脑。那时候只要模型本身能力再往前推一点，大家都会觉得是大事。

现在这条线当然还会继续卷，但行业注意力已经在明显分流。

一个方向，是大家开始更认真地做 Agent 应用。你可以把“养龙虾”理解成这条线的一个非常典型的现实入口：不是继续抽象卷模型，而是先让模型在一个真实工作流里跑起来，先把工具调用、多步执行、持续运行这些事做稳。

另一个方向，就是多智能体协同。

因为当单个模型已经足够强之后，下一个自然问题就是：**能不能不是只让一个模型更聪明，而是想办法把一群模型组织起来，让它们真的比单个模型更能干活。**

这也是为什么我会觉得，接下来更值得看的，不只是单兵能力，而是组织方式。

在这件事上，我觉得 Kimi 和 MiniMax 已经是国内现在最值得重点观察的两条路线。

MiniMax M2.7 这次之所以值得单独拿出来说，就是因为它对这个问题给出了一个相对清楚的答案。

它给出的答案，叫 Agent Teams。

如果只看官方词汇，这个词其实没什么特别，谁都可以说自己在做 agent team。真正关键的是，它拿什么来支撑这件事。

目前公开材料里，我觉得真正值得留的证据不需要很多，几条就够了。

第一条，是它已经被放进了自己的 RL 研发流程里。官方说，M2.7 可以处理 **30%-50% 的工作流**，覆盖文献回顾、实验 spec 跟踪、数据和 artifact 管理、启动实验、监控进度、读日志、debug、分析指标、修代码、提 merge request、跑 smoke test。

这条信息为什么重要？因为它说明 M2.7 展示的不是“会回答研究问题”，而是“开始参与研究流程”。

第二条，是它的自主迭代方式。MiniMax 给出的说法是，M2.7 在 internal scaffold 上连续跑了 **100 多轮** “分析失败轨迹—计划修改—改 scaffold—跑评测—比较结果—决定保留或回滚”的循环。另一组公开测试里，它在 **MLE Bench Lite** 的 22 个任务上做了三次 **24 小时自主迭代**，最好的一次拿到 **9 金 5 银 1 铜**，三次平均奖牌率 **66.6%**。

这条信息值得看的地方，也不只是 66.6% 这个数字本身，而是它说明这个系统不是只会单次给答案，而是能在很长时间里继续往前推任务、回看结果、做修正。

第三条，是它在复杂环境里的稳定性。公开资料里提到，在 **40 个复杂 skills**、每个 skill 定义都超过 **2000 tokens** 的环境里，它还能保持 **97% 的 skill adherence**。

这个数字不花哨，但它非常关键。因为很多模型的问题不是不会，而是到了复杂系统里容易跑偏、容易掉链子。97% 这个数字更像是在说明：它不仅强，而且在复杂约束环境里相对稳。

把这几条放在一起看，我觉得 MiniMax 这次真正值得看的，不只是它作为一个模型又强了一点，而是它越来越像一个可以被放进复杂系统里持续工作的模型。

这也是为什么我会把它理解成一支**小型战术小队**。

它的重点不是规模化并发，而是补位、找错、回看、修正、收敛。你去看它用来证明自己的材料，核心都不是“我一次能调多少个 agent”，而是“我能不能在复杂任务里一路盯下去，把事情继续推完”。

而 Kimi 2.5 的 Agent Swarm，则更像另一种答案。

我更愿意把它理解成一条**规模化流水线**。

它现在更鲜明的特点，是并发、拆解、分发执行和稳定交付。资料里提到它可以协调多达 **100 个子智能体**并行工作，这种路线天然适合广度搜索、任务拆解、批量推进这类事情。

所以这两者真正值得讨论的，不是谁更先进。

更准确地说，是：**什么任务更适合什么组织方式。**

如果你的任务更怕出错，比如深度研究、复杂 debug、财务建模、长链路项目交付，那 MiniMax 这种更像小队的系统会更有价值。因为这种任务最需要的不是并发，而是回看、纠偏和收敛。

如果你的任务更怕漏想，比如广度搜索、海量资料整理、大规模信息覆盖，那 Kimi 这种更像流水线的系统会更有价值。因为这种任务最需要的是并发、吞吐和覆盖率。

所以对普通用户来说，这件事最后其实会落到一个很具体的判断上：以后选 AI，除了看能力和性价比，还要看你的任务到底更需要什么样的团队。

你找的，不只是一个模型，而是一支 AI 团队。

如果你的任务更怕出错，就更适合找一个像流水线一样稳定执行的系统。
如果你的任务更怕漏想，就更适合找一个像小队一样会补位和纠偏的系统。

所以如果这篇最后只收一句话，我会写得很简单：

**MiniMax M2.7 这次最值得看的，不只是它更强了，而是它把“多智能体团队到底该怎么组织”这个问题，第一次讲得比较具体了。**

而这件事，对普通用户来说，不只是一个技术趋势，而是以后你真的可以开始按任务类型去选一支 AI 团队。
