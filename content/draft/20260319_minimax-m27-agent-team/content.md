# MiniMax M2.7 母稿（重写版）

MiniMax M2.7 刚发布时，我第一反应其实也很普通：又一个国产模型更新了，接下来无非就是看它和 GPT、Claude、Gemini 这些头部模型的差距又缩小了多少。

但把资料认真翻完之后，我觉得这次最值得写的点，不在这里。

M2.7 值得看的，不只是它又强了一点，而是它开始把一个更大的问题摆到台面上：**以后模型之间真正拉开差距的，可能不只是单体能力，而是怎么把一群 AI 组织成一个能工作的团队。**

这个判断不是空出来的，我先把我觉得最值得看的几个事实摆出来。

第一，MiniMax 官方给出的信息里，M2.7 已经被放进它自己的研发闭环里了。官方说得很具体：在 RL 团队日常实验流程里，M2.7 可以参与文献回顾、跟踪实验 spec、管数据和其他 artifact、启动实验、监控进度、读日志、调试、分析指标、修代码、提 merge request、跑 smoke test。官方给出的范围是，它能处理 **30%-50% 的工作流**。

这条信息为什么重要？因为它说明 M2.7 展示的不是“会回答研究问题”，而是“已经开始参与研究流程”。这和过去那种单轮问答式的强模型，不是一回事。

第二，官方还给了一组更像能力边界测试的数据：他们让 M2.7 在一个简化的自优化 harness 里，围绕失败轨迹分析、修改 scaffold、运行评测、比较结果、决定保留或回滚，连续跑了 **100 多轮**。另一组测试里，他们让 M2.7 在 MLE Bench Lite 的 22 个机器学习竞赛任务上做三次 **24 小时自主迭代**。最后给出的结果是：最好的一次拿到 **9 金 5 银 1 铜**，三次平均奖牌率 **66.6%**。

这条信息也很关键。它不只是说明“模型会自己试”，而是说明它已经能在一个比较长的时间尺度里，靠短期记忆、自我批评和自我修正，持续往前推任务。这里面当然有 harness 设计的功劳，不是说模型脱离系统就能自己完成一切，但至少说明：它的能力重点，已经不是单次回答，而是闭环推进。

第三，M2.7 这次在软件工程相关 benchmark 上的数字也值得看。官方给出来的是：
- **SWE-Pro 56.22%**
- **VIBE-Pro 55.6%**
- **Terminal Bench 2 57.0%**
- **SWE Multilingual 76.5**
- **Multi SWE Bench 52.7**
- **NL2Repo 39.8**

这些数字本身不是文章的结论，但它们能说明一件事：M2.7 这次不是只在抽象推理层面讲故事，它是把重点放在了更接近真实工程环境的长链路任务上。尤其是官方自己举的那个线上故障排查场景，虽然带有展示性质，但它至少说明 MiniMax 想证明的不是“模型会写代码”，而是“模型能理解系统、能排查问题、能在复杂环境里收敛”。

第四，M2.7 对多智能体团队的强调也比一般的 agent 宣传更具体。官方原话里明确提到 **native Agent Teams**，还特别强调几件事：
- role boundaries
- adversarial reasoning
- protocol adherence
- behavioral differentiation

它的说法是，这些能力不是靠 prompting alone 就能稳定实现，而要作为模型的原生能力去内化。这个说法我觉得可以看，但不能全信。因为到目前为止，我没有看到特别扎实的公开消融实验，来证明“原生内化”相比“prompt + workflow 编排”到底强多少。所以这部分更稳的写法应该是：**MiniMax 明显把多智能体协作机制当成底层设计重点来做**，但不宜直接写成它已经彻底证明了 prompt 编排落后。

第五，M2.7 在专业办公和复杂技能环境里的数据也值得留一下。公开资料里有：
- **GDPval-AA ELO 1495**
- **40 个复杂 skills 上 97% skill adherence**
- **MM Claw 62.7%**

这些数字说明的不是“它能做 office”，而是它在复杂环境下的稳定性比前一代更像回事。尤其是 skill adherence 这个点，我觉得很重要。很多模型的问题不是不会做，而是中途跑偏、参数乱传、技能调用不稳。如果一个模型在 40 个复杂技能里还能把遵循率压到 97%，那至少说明它在复杂系统里的行为一致性是有进步的。

把这些信息放在一起，我为什么会觉得这次最值得看的，不只是“更强”，而是“组织智能”？原因很简单：这些证据大多都不是在证明 M2.7 单轮回答更惊艳，而是在证明它更适合放进一个需要持续推进、持续修正、持续收敛的系统里。

这也是为什么我后来会想到 Kimi2.5 Agent Swarm 和 MiniMax M2.7 的那个对比。

这个对比我现在会写得更克制一点。

Kimi 更像流水线团队，MiniMax 更像战术小队——这个比喻我还是觉得成立，但它应该被理解成**当前更鲜明的产品范式差异**，而不是绝对能力边界。

为什么我会把 Kimi 理解成更像流水线？因为它那套 Agent Swarm 给人的主要感觉是：高并发、分发执行、结构清晰、编排稳定。它更像是在解决“任务怎么拆开、怎么并行、怎么尽量不出错”。这类系统对很多真实业务很重要，尤其是那些标准化、可拆解、风险敏感的任务。

为什么我会把 MiniMax 理解成更像战术小队？因为从它这次对外讲的重点和它给出的例子来看，它更强调的是：角色边界、结果验证、自我批评、长链路任务里的纠偏和收敛。它不只是想证明一群 agent 可以一起工作，而是想证明这群 agent 可以在复杂任务里互相补位、互相找错，然后把任务做得更完整一点。

这两个方向，我觉得都成立，也都不会是通用解。

对普通用户来说，这件事真正重要的地方，不是你后台到底开了几个 agent，也不是你底层到底是不是原生多智能体。普通用户真正关心的，还是很朴素的三个问题：
- 交给你会不会翻车
- 我没想到的地方你能不能补上
- 我到底该把你当执行工具，还是协作伙伴

所以这件事最后落到使用层，我觉得可以收成一句很直接的话：

**你最怕出错，就选更像流水线的系统；你最怕漏想，就选更像小队的系统。**

这句话不高级，但我觉得是有用的。

如果你的任务是标准化整理、固定格式交付、流程清楚、风险又比较高，那流水线型团队就很有价值。它不一定最惊艳，但大概率更稳。

如果你的任务是复杂研究、debug、方案推演、需要边做边修、边做边查漏，那小队型团队会更有价值。因为这种场景真正稀缺的，不是执行，而是补位。

最后我想说一个更大的判断，但这句话也要写得克制。

过去我们聊国内模型，很多时候默认叙事还是“追赶”。在很多基础能力上，这个判断到现在也没有完全失效。

但如果把视角放到“怎么把一群 AI 组织成一个能工作的团队”这件事上，我觉得中国团队已经开始进入前沿竞争区了。

这里不能写成“已经全面领先”，也不能写成“已经超过所有海外模型”。更稳的说法应该是：**在很多单点能力上，国内模型还在追；但在组织智能这件事上，国内团队已经开始拿出自己的方法论。**

Kimi 这条线在回答“怎么把一群 agent 稳定组织起来去并发干活”，MiniMax 这条线在回答“怎么让一群 agent 在复杂任务里做补位、纠偏和收敛”。这两条路本身，就已经是一个信号了。

所以我现在看 MiniMax M2.7，最强的感受不是“又一个热点模型来了”，而是：它让“多智能体竞争到底在比什么”这件事更清楚了一点。

过去大家更容易把注意力放在模型排行榜上。这个当然还会继续重要。

但接下来真正值得持续看的，可能是另一条线：

**谁更会组织智能。**

我觉得这件事，比单纯讨论它又追近了谁，更值得写。
