# MiniMax M2.7 母稿（第三版）

MiniMax M2.7 刚发布时，最容易被看到的当然还是那几个热点词：自我进化、编程能力、性价比、又往头部闭源模型靠近了一点。

这些都是真的。

比如从公开材料看，M2.7 在 **SWE-Pro** 上做到 **56.22%**，在 **Terminal Bench 2** 上做到 **57.0%**，在 **VIBE-Pro** 上是 **55.6%**。如果只把它当成一个新的编程模型来看，这些分数已经足够说明它很能打。

但我看完资料之后，反而觉得这不是这次最值得写的地方。

更值得写的，是它开始碰一个更难也更现实的问题：**多智能体团队到底该怎么组织。**

我为什么会这么判断，不是因为官方讲了“Agent Teams”这个词，而是因为它拿出来的几条证据，已经不只是单次回答能力的证据了。

第一条最值得看的，是 MiniMax 官方自己披露的内部使用方式。它不是说 M2.7 帮研究员润色报告、写点代码，而是说它已经被放进了 RL 研发流程里，处理 **30%-50% 的工作流**。这里面包括文献回顾、跟踪实验 spec、管理数据和 artifact、启动实验、监控进度、读日志、debug、分析指标、修代码、提 merge request、跑 smoke test。

这条信息的重要性在于，它说明 M2.7 展示的不是“回答研究问题”，而是“参与研究流程”。

如果一个模型只是把代码写得更漂亮，或者把答案讲得更完整，那它再强，本质上也还是一个单点工具。
但如果它开始被放进一整条工作流里，而且承担的是监控、修正、推进这些环节，那它的价值就不再只是单体能力，而是更适合放进系统里工作。

第二条更关键，是它的自主迭代方式。官方给出的说法是，M2.7 在一个 internal scaffold 上，反复执行“分析失败轨迹、计划修改、改 scaffold、跑评测、比较结果、决定保留还是回滚”的循环，连续跑了 **100 多轮**。另一个更公开的测试里，它在 **MLE Bench Lite** 的 22 个任务上做了三次 **24 小时自主迭代**，最好的一次拿到 **9 金 5 银 1 铜**，三次平均奖牌率 **66.6%**。

我觉得这里真正值得看的，不是 66.6% 这个数字本身，而是这组测试在考什么。

它考的已经不是“单次回答漂不漂亮”，而是这个系统能不能在很长时间里持续往前推任务，能不能在失败后继续调整，能不能不靠人一步一步盯着它还把事情做下去。

资料里提到它依赖的是几个模块：短期记忆、自我反馈、自我优化。说白了，就是它不是只答一下，而是会记、会回看、会挑自己毛病、会下一轮继续改。

这就是为什么我会觉得，这次更值得看的，不只是模型更强，而是它越来越像一个可以被放进持续协作、持续纠偏、持续收敛系统里的东西。

第三条能补强这个判断的，是它在复杂环境里的稳定性。公开资料里有一个数字我觉得比很多 benchmark 更重要：在 **40 个复杂 skills**、每个 skill 定义都超过 **2000 tokens** 的环境里，它还能保持 **97% 的 skill adherence**。

这条数据不花哨，但很有用。

因为很多模型的问题不是完全不会，而是到了复杂环境里容易跑偏，工具乱调，参数乱传，前面做得不错，后面突然掉链子。97% 这个数字说明的不是“它更聪明”，而是“它在复杂系统里更稳”。

这点和前面那几条放在一起，就比较能支撑一个更具体的判断：

**M2.7 这次值得看的，不只是它作为单个模型又强了一点，而是它开始展示一种更适合进入复杂系统、承担连续任务、并在过程中自我修正的能力。**

这也是为什么我觉得，这次如果只写“它又追近了谁”，会有点可惜。

因为真正的新意，不在“追近”本身，而在它开始认真回答：一群 AI 到底怎么一起工作。

把这个问题放大一点看，其实不只是 MiniMax 在碰。

最近你会发现，主流厂商已经开始把注意力往 Agent 应用和多智能体协同上放。智谱前面刚出了一个更偏 OpenClaw / “龙虾”场景的 GLM-5-Turbo，重点不是把聊天体验再卷一轮，而是把模型往长链路执行、工具调用稳定性、多步任务跑完这件事上调。这里面当然有“先把 Agent 真用起来”的现实考量。

这背后其实有个很朴素的行业变化：

单点模型能力当然还有继续提升的空间，但这条线的边际收益，已经没有前两年那么夸张了。厂商还是会继续卷单兵能力，但另一条线已经越来越重要：怎么让一群模型通过组织方式，真的比单个模型更能干活。

在这件事上，我觉得 Kimi 和 MiniMax 是国内现在最值得重点观察的两条路线。

Kimi 2.5 的 Agent Swarm，更像一条规模化流水线。

这么说不是因为它不够复杂，而是因为它现在更鲜明的特点就是并发、拆解、分发执行、稳定交付。资料里提到它可以协调多达 **100 个子智能体**并行工作，这种能力天然适合广度搜索、批量处理、任务拆解之后的大规模推进。

MiniMax M2.7 的 Agent Teams，则更像一支小型战术小队。

它现在更鲜明的特点不是并发规模，而是补位、找错、回看、修正、收敛。你去看它拿出来证明自己的材料，重点都不是“我能并发调多少 agent”，而是“我能不能在复杂任务里一路盯下去，把事情继续推完”。这就是为什么我会把它理解成一支小队，而不是一条流水线。

这里真正值得讨论的，不是谁更先进。

更准确地说，是：**什么任务更适合什么组织方式。**

如果你的任务更怕漏想，比如大规模搜索、广度情报收集、海量材料整理，那流水线型系统会更有价值。因为它强在并发、覆盖和吞吐。

如果你的任务更怕出错，比如深度研究、复杂 debug、财务建模、长链路项目交付，那小队型系统会更有价值。因为它强在回看、纠偏、补位和收敛。

所以对普通用户来说，这件事最后会落到一个很实际的判断上：以后选 AI，除了看能力和性价比，还要看你的任务到底更需要什么样的团队。

你可以找的，不只是一个模型，而是一支 AI 团队。

如果你的任务更怕出错，就更适合找一个像流水线一样稳定执行的系统。
如果你的任务更怕漏想，就更适合找一个像战术小队一样会补位和纠偏的系统。

最后我想把这个判断再收得稳一点。

我现在不会写“国内模型已经在这件事上全面领先”，因为证据还不支持这么满的结论。

但我觉得可以写另一句更稳的话：**在“怎么组织一群 AI 干活”这件事上，国内团队已经开始拿出比较清楚的方法路线，而且很值得重点观察。**

Kimi 是一条路，MiniMax 是另一条路，智谱围绕 OpenClaw / 龙虾场景做的专项优化也是一条现实落地方向。

这些路线未必已经分出胜负，但它们至少说明，国内现在不只是跟着追单点能力，也开始在“组织智能”这件事上给出自己的答案。

所以如果现在让我用一句话收这篇，我会写得很简单：

**MiniMax M2.7 这次最值得看的，不只是它更强了，而是它让“多智能体团队到底该怎么组织”这个问题，第一次变得具体了。**

这件事，我觉得比它又追近了谁，更值得继续往下看。
